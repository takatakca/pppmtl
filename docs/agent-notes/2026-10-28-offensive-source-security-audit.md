## Findings — source proved, narrow regression patches

| Severity | Entry point and actual weakness before fix | Mitigation in PR #22 | Negative-test evidence |
|---|---|---|---|
| Medium/high availability | `POST /api/public/webhooks/provider?provider=urbanpiper` used unlimited `request.text()` after checking that a secret existed, **before** verifying HMAC. Any unauthenticated request to a configured endpoint could consume memory/CPU through large data. | Uses the shared **128-KiB streaming** `readBoundedWebhookBody`; refuses oversized declared or chunked bodies with HTTP 413 and unparseable streams with 400. Neither signed request nor payment needed. | `src/lib/integration/__tests__/provider-ingress.test.ts`: streamed oversized request, forged Content-Length, unsigned small payload; actual route handler invoked without network. |
| High integrity, conditional on provider callbacks | `findOrderByProviderId(id)` assumed all third-party IDs globally unique. A valid signed UrbanPiper status update could alter a Clover order if IDs collided; a Clover payment could map to the wrong provider's order. | Provider identity is now a **mandatory argument** to stored-order lookup. `applyProviderStatusUpdate("urbanpiper", ...)` and `applyCloverPayment("clover", ...)` can only mutate the matching provider's order. | `src/lib/orders/__tests__/webhook-provider-isolation.test.ts`: same ID across two provider records, reversed save order and missing/wrong-provider IDs. |
| High potential merchant operations (currently sandbox only; production checkout already blocked) | For a valid Clover signature and merchant ID, the prior sandbox handler could call Clover REST to **title/print a payment without matching any PPP checkout** (`applyCloverPayment` returned `null`, but `confirmInClover` still ran). This becomes unsafe if future production persistence is enabled incorrectly. | Before any remote Clover REST action, require a **tracked PPP Clover checkout-session mapping**. For untracked signed events return retryable 503 (30 s), release in-process claim, do not title or print, and log only an opaque reference. | `src/lib/integration/__tests__/clover.test.ts`: valid signed, correct merchant, unrelated session is refused *before* Clover REST/printing; retry remains retryable. |
| Medium/high integrity | Existing Clover checkout payment association could be overwritten by a later **different payment ID**; an approved callback after `CANCELLED` or `FAILED` could mark a terminal order paid. | Immutable payment-ID association once set; refuse callbacks on cancelled/failed orders for manual reconciliation rather than automate print. | Provider-isolation tests cover replacing payment ID, same-ID replay, cancelled/failed status. |

The pre-existing Clover production lock remains **unchanged**: `src/lib/orders/order-store.server.ts` has `ordersPersistAcrossRestarts=false`; `CLOVER_ENV=production` cannot create Hosted Checkout or automatically reconcile payments in this state. All Clover network calls in tests are **mocked**. No real credentials are used in test data.

## Still open — critical gates (not solved by a green test suite)

1. **No real checkout** until #5/#6/#13: approved production PostgreSQL 15+/backups/recovery and deployed migrations; verified TAKATAK tenant claims and RBAC; signed merchant-scoped Clover webhook linked to an immutable checkout/payment; transactional durable inbox, dedup, outbox/worker and retry quarantine; controlled restart, replay and manual-review tests. A CI-only ephemeral DB does not meet this.
2. **Multi-worker replay state remains volatile.** `src/lib/integration/core/webhook-security.ts` keeps only a process-local 500-event ring; `logging.ts` uses an in-memory idempotency ring. Confirm official provider timestamp signing (the generic verifier currently supports timestamped and body-only HMAC) and implement durable provider-scoped replay detection. Do **not** silently change signature compatibility before confirmed UrbanPiper contract.
3. **Admin access:** the app uses a single temporary strong server-secret bootstrap cookie, not verified TAKATAK tenant RBAC. Edge trust/rate limits and admin access auditing remain to be proven with the authorized hosting operator; avoid an IP spoofable proxy-based limiter.
4. **Production proof/defense-in-depth:** verify exact SHA and recent health in **native Coolify** app UUID `r13hz1mmbi4eeoc6ssxbvxnv`, proxy security headers, no secrets exposed in bundles, anonymous `/dev/menu-audit` 401 no-store, unauthenticated admin actions 401, `GET /api/public/webhooks/clover` 405, oversized payload rejection on **authorized staging only**, CSP/iframe protections (parallel PR #21), backup and rollback. Never probe production with high traffic, customer tokens, fuzzing of paid endpoints or real provider callbacks without a separately approved window.
5. **Shared-branch discipline:** do not merge PR #22 blindly with PR #21/#19. If their changes touch the same files or security headers, rerun the entire CI on the eventual merged SHA and verify native Coolify rollout before release. No force-push.
